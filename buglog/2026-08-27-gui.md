用户在 GUI 验收时设置页插件列表显示"暂时无法读取插件。"+重试按钮。排查链：(1) 错误文案定位于 ui-settings-plugin-inventory 的 list() Promise 拒绝分支；(2) 磁盘态全部健康——重建后的 lib/index.js 可直接 import 成功、@deepseek-ai/dsh-home-paths 在 pnpm 布局下解析正常（node_modules 符号链接存在）、web dist 已刷新至 12:27；(3) 对比时间线发现关键错位：旧服务进程 PID 17432 于 10:19 启动，内存中仍是改动前契约（PluginInventoryEntry 无必填 description 字段），而 12:26–12:38 全量构建重生了磁盘产物与新前端；浏览器加载新前端后按必填字段严格解码旧进程载荷即抛错，组件呈现通用失败态。修复为重启服务：终止旧进程并以 node apps\cli\lib\bin.js web 重新启动。经验教训：改 Host 服务契约后必须重启长驻的 dsh web 进程，否则新客户端配旧宿主会以通用错误呈现，掩盖真实根因。早期怀疑的 profiles/web/node_modules 缺符号链接、依赖未装均为红鲱鱼——dsh web 实际从仓库工作区解析包而非该目录。
